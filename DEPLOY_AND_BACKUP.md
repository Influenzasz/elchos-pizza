# Руководство по развертыванию, эксплуатации и резервному копированию (Deployment & Backup Guide)

Комплексная инженерная инструкция по установке, сетевой настройке, обслуживанию и аварийному восстановлению системы «Elcho's Pizza Enterprise Suite».

---

## 1. Системные требования и архитектурное окружение

Программный комплекс спроектирован по концепции **Zero-Dependency On-Premise**, что исключает необходимость предустановки сторонних СУБД (PostgreSQL, MS SQL, MySQL), контейнеров Docker или тяжелых веб-серверов (IIS, Apache).

### Аппаратные требования:
- **Центральный сервер:** Любой офисный ПК или выделенный сервер (2 ядра CPU, от 1 ГБ RAM, от 500 МБ дискового пространства);
- **Рабочие станции (Касса, Кухня, Киоск, Табло):** Сенсорные POS-моноблоки, планшеты, ТВ-панели с поддержкой браузера Chromium/Edge;
- **Сетевая инфраструктура:** Локальная проводная сеть Ethernet (100–1000 Мбит/с) или корпоративная сеть Wi-Fi 2.4/5 ГГц.

### Программные требования:
- **Операционная система:** Microsoft Windows 7 SP1, Windows 8.1, Windows 10, Windows 11, Windows Server 2012/2016/2019/2022 (x86/x64);
- **Среда выполнения:** Microsoft .NET Framework 4.0 или выше (встроена во все современные версии Windows);
- **Браузер:** Любой браузер на базе Chromium (Google Chrome, Microsoft Edge, Яндекс Браузер) для нативных лаунчеров `--app`.

## 2. Развертывание системы за 3 минуты (Быстрый старт)

### Шаг 1: Размещение дистрибутива
Скопируйте каталог проекта в целевую директорию на сервере (например, `C:\ElchosPizza` или используйте рабочий каталог `d:\Dokumente\gemini`).

### Шаг 2: Настройка сетевого порта (при необходимости)
В файле `project/appsettings.json` укажите порт прослушивания:
```json
{
  "Server": {
    "Port": 5000,
    "Host": "*"
  }
}
```
*Примечание:* По умолчанию сервер биндится на порт `5000` и доступен как локально (`127.0.0.1:5000`), так и по локальной сети (`http://IP_СЕРВЕРА:5000`).

### Шаг 3: Запуск сервера
Запустите командный файл:
```cmd
Запуск_Пиццерии.bat
```
Скрипт автоматически запустит фоновый процесс `Сервер.exe` и откроет стартовую страницу в браузере.

### Шаг 4: Развертывание клиентских рабочих станций
На соответствующих терминалах персонала запустите нужный лаунчер из каталога `приложения/`:
- **Терминал кассира:** `приложения\Касса_POS.exe`
- **Кухонный монитор:** `приложения\Кухня_KDS.exe`
- **Электронное табло в зале:** `приложения\Табло_Очереди.exe`
- **Киоск самообслуживания:** `приложения\Киоск_Заказа.exe`
- **Компьютер управляющего:** `приложения\Администратор.exe`
- **Мобильный терминал курьера:** открыть в браузере мобильного устройства адрес `http://IP_СЕРВЕРА:5000/courier`.

## 3. Сетевая топология и правила брандмауэра (Firewall)

Для корректной работы станций в локальной сети предприятия необходимо открыть входящий TCP-порт сервера (по умолчанию `5000`).

Выполните команду в PowerShell от имени Администратора на сервере:
```powershell
New-NetFirewallRule -DisplayName "Elchos Pizza POS Server" -Direction Inbound -LocalPort 5000 -Protocol TCP -Action Allow
```

## 4. Резервное копирование базы данных (Backup & Restore)

База данных пиццерии хранится в файле `project/pizza.db` и работает в высокопроизводительном режиме **WAL (Write-Ahead Logging)**.  
В режиме WAL база данных состоит из трех связанных файлов:
1. `pizza.db` — основной файл реляционной базы данных;
2. `pizza.db-wal` — оперативный журнал предзаписи транзакций;
3. `pizza.db-shm` — файл индекса разделяемой памяти.

### 4.1. Горячее резервное копирование (без остановки сервера)

> [!IMPORTANT]
> При создании резервной копии «на лету» критически важно копировать все три файла (`.db`, `.db-wal`, `.db-shm`) одновременно либо выполнять сброс WAL в основную базу (Checkpoint).

#### Скрипт автоматического бэкапа (PowerShell):
Создайте сценарий `Backup_Pizza_DB.ps1`:
```powershell
$SourceDir = "d:\Dokumente\gemini\project"
$BackupDir = "D:\Backups\Pizza_" + (Get-Date -Format "yyyyMMdd_HHmmss")
New-Item -ItemType Directory -Path $BackupDir -Force | Out-Null

# Копирование триплета файлов SQLite WAL
Copy-Item "$SourceDir\pizza.db*" -Destination $BackupDir -Force

Write-Host "Резервная копия базы данных успешно создана в: $BackupDir" -ForegroundColor Green
```

### 4.2. Настройка расписания бэкапа (Windows Task Scheduler)
Для ежедневного автоматического бэкапа в конце смены (например, в 23:30) добавьте задачу в планировщик Windows:
```cmd
schtasks /create /tn "ElchosPizza_DailyBackup" /tr "powershell.exe -ExecutionPolicy Bypass -File D:\Dokumente\gemini\Backup_Pizza_DB.ps1" /sc daily /st 23:30
```

### 4.3. Аварийное восстановление (Disaster Recovery)

В случае сбоя оборудования или непредвиденного повреждения накопителя:
1. Завершите процесс `Server.exe` (или `Сервер.exe`) через диспетчер задач или команду `taskkill /F /IM Server.exe`.
2. Перейдите в каталог последней валидной копии `D:\Backups\Pizza_YYYYMMDD_HHMMSS`.
3. Скопируйте файлы `pizza.db`, `pizza.db-wal`, `pizza.db-shm` с заменой в папку `project/`.
4. Запустите `Сервер.exe`.
5. Запустите верификатор `Тест_Системы.exe` для подтверждения целостности базы данных и прохождения всех 40 тестов.

## 5. Мониторинг, диагностика и логирование

1. **Журнал событий:** В панели администратора (`/admin` -> вкладка «Аудит») ведется протокол действий персонала (входы, смены статусов, фискальные операции).
2. **Проверка работоспособности (Healthcheck):** Вызов `GET http://127.0.0.1:5000/api/categories` возвращает HTTP 200 OK при штатной работе.
3. **Автоматическая верификация:** В любой момент можно запустить `Тест_Системы.exe` — скрипт за 1.5 секунды валидирует каталог, кассу, кухню, склад и модель ролевого доступа.
