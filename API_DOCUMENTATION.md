# Спецификация контрактов REST API — Elcho's Pizza Enterprise Suite

Полная техническая документация прикладных программных интерфейсов (API) автоматизированной системы управления пиццерией и сервисом экспресс-доставки ООО «Элчос Пицца».

---

## 1. Общие сведения и сетевой протокол

- **Базовый URL:** `http://127.0.0.1:5000` (настраивается в `appsettings.json`)
- **Формат обмена данными:** JSON (`application/json; charset=utf-8`)
- **Протокол реального времени:** Server-Sent Events (SSE) через эндпоинт `/api/events/subscribe`
- **Модель авторизации:** Role-Based Access Control (RBAC). Роли передаются в заголовке авторизации либо в сессионном контексте.
- **Стандартные коды возврата HTTP:**
  - `200 OK` — Успешное выполнение запроса;
  - `400 Bad Request` — Ошибка валидации входных данных (отсутствие обязательных полей);
  - `401 Unauthorized` — Пользователь не аутентифицирован;
  - `403 Forbidden` — Доступ запрещен (недостаточно привилегий по модели RBAC);
  - `404 Not Found` — Запрашиваемый ресурс (товар, заказ, смена) не найден;
  - `500 Internal Server Error` — Необработанная ошибка серверного ядра.

## 2. Аутентификация и пользователи (`/api/auth`)

### 2.1. Вход в систему (Login)
- **Метод и маршрут:** `POST /api/auth/login`
- **Доступ:** Публичный
- **Тело запроса:**
```json
{
  "login": "admin@elchos.ru",
  "password": "admin123"
}
```
- **Успешный ответ (200 OK):**
```json
{
  "success": true,
  "message": "Авторизация успешна",
  "user": {
    "id": 1,
    "email": "admin@elchos.ru",
    "fullName": "Главный Администратор",
    "role": "admin"
  }
}
```
- **Ошибка (400/401):** `{"success": false, "message": "Неверный логин или пароль"}`

### 2.2. Регистрация клиента (Register)
- **Метод и маршрут:** `POST /api/auth/register`
- **Доступ:** Публичный
- **Тело запроса:**
```json
{
  "email": "client@example.com",
  "phone": "+79991234567",
  "password": "strongPassword123",
  "fullName": "Иван Петров",
  "address": "ул. Гагарина, д. 15, кв. 42"
}
```
- **Успешный ответ (200 OK):**
```json
{
  "success": true,
  "message": "Регистрация успешно завершена",
  "userId": 5
}
```
- **Валидация:** При попытке зарегистрировать уже существующий Email возвращается `{"success": false, "message": "Пользователь с таким email уже существует"}`.

### 2.3. Быстрый демо-вход персонала (Demo Login)
- **Метод и маршрут:** `POST /api/auth/demo-login`
- **Доступ:** Публичный (для автономных рабочих станций)
- **Тело запроса:** `{"role": "cashier"}` (варианты: `admin`, `cashier`, `chef`, `courier`, `client`)
- **Ответ (200 OK):** Объект пользователя с закрепленной ролью.

## 3. Каталог меню и модификаторы (`/api/products`, `/api/categories`)

### 3.1. Получение категорий
- **Метод и маршрут:** `GET /api/categories`
- **Ответ (200 OK):** Массив объектов категорий:
```json
[
  { "id": 1, "name": "Пиццы", "sortOrder": 1, "icon": "pizza" },
  { "id": 2, "name": "Закуски", "sortOrder": 2, "icon": "snack" },
  { "id": 3, "name": "Напитки", "sortOrder": 3, "icon": "drink" },
  { "id": 4, "name": "Десерты", "sortOrder": 4, "icon": "dessert" },
  { "id": 5, "name": "Соусы", "sortOrder": 5, "icon": "sauce" },
  { "id": 6, "name": "Комбо", "sortOrder": 6, "icon": "combo" }
]
```

### 3.2. Получение списка блюд
- **Метод и маршрут:** `GET /api/products`
- **Ответ (200 OK):** Массив из 44 позиций меню с ценами, калорийностью, флагами стоп-листа и путями к оригинальным фотографиям высокой четкости (`/img/pizza_1.png`).

### 3.3. Размеры, тесто и ингредиенты
- `GET /api/sizes` — Список доступных диаметров пицц: Маленькая (25 см, коэф. 0.8), Средняя (30 см, коэф. 1.0), Большая (35 см, коэф. 1.25).
- `GET /api/doughtypes` — Типы основы: Традиционное и Тонкое тесто.
- `GET /api/toppings` — Список 13 добавок и бортиков (Сырный бортик, Бекон, Шампиньоны, Халапеньо и др.) с фиксированной стоимостью.

### 3.4. Управление меню (Только роль `admin`)
- `POST /api/products/save` — Создание или редактирование параметров блюда.
- `POST /api/products/toggle` — Включение / отключение позиции (стоп-лист).
- `POST /api/products/delete` — Удаление позиции. При вызове не администратором возвращается `HTTP 403 Forbidden`.

## 4. Жизненный цикл заказов (`/api/orders`)

### 4.1. Оформление заказа (Клиент / Киоск)
- **Метод и маршрут:** `POST /api/orders`
- **Тело запроса:**
```json
{
  "orderType": "Delivery",
  "customerName": "Алексей Смирнов",
  "customerPhone": "+79270001122",
  "deliveryAddress": "ул. Садовая, д. 20, кв. 5",
  "paymentMethod": "CardOnline",
  "promoCode": "ELCHOS20",
  "discountAmount": 240,
  "items": [
    {
      "productId": 1,
      "productName": "Elcho's Special",
      "sizeName": "Большая 35 см",
      "doughName": "Традиционное",
      "selectedToppings": ["Сырный бортик", "Бекон"],
      "unitPrice": 899,
      "quantity": 1
    }
  ]
}
```
- **Бизнес-логика выполнения:**
  1. Сервер регистрирует запись в таблице `Orders` с уникальным кодом (например, `#1042`).
  2. В рамках атомарной транзакции списываются граммы сырья из таблицы `Inventory` (WMS) согласно технологической карте выбранного размера.
  3. Через `EventBus` отправляется широковещательное событие на экран кухни (KDS).
- **Ответ (200 OK):** `{"success": true, "orderId": 42, "orderNumber": "1042"}`

### 4.2. Смена производственного статуса (Кухня / Курьер)
- **Метод и маршрут:** `POST /api/orders/{id}/status`
- **Тело запроса:** `{"status": "Cooking"}`
- **Допустимые статусы (State Machine):**
  - `New` — Заказ принят системой;
  - `Cooking` — Повар взял в работу (сборка начинки);
  - `Oven` — Пицца отправлена в печь (300°C);
  - `Ready` — Блюдо упаковано, отображается на табло в зале;
  - `OnTheWay` — Заказ передан курьеру в доставку;
  - `Delivered` — Заказ вручен клиенту;
  - `Cancelled` — Заказ аннулирован.

### 4.3. Выборки по станциям
- `GET /api/orders/kitchen` — Заказы в статусах `New`, `Cooking`, `Oven` с составом модификаторов и таймерами.
- `GET /api/orders/board` — Сводка для электронного табло зала: списки `preparing` и `ready`.
- `GET /api/orders/courier` — Заказы со статусом `Ready` и `OnTheWay`, адресами и контактами.
- `GET /api/orders/track?phone={phone}&number={num}` — Онлайн-трекинг этапа приготовления для гостей.

## 5. Кассовый терминал и фискализация по 54-ФЗ (`/api/pos`, `/api/shifts`)

### 5.1. Управление кассовыми сменами
- `GET /api/shifts/current` — Получение статуса текущей открытой смены кассира.
- `POST /api/shifts/open` — Открытие фискальной смены (с внесением разменного фонда).
- `GET /api/shifts/x-report` — Печать промежуточного X-отчета кассира (выручка без гашения регистров).
- `POST /api/shifts/close` — Закрытие фискальной смены с генерацией Z-отчета, инкассацией и гашением кассовых регистров. При попытке закрытия не кассиром/администратором возвращается `HTTP 403 Forbidden`.

### 5.2. Пробитие чека на кассе (POS)
- **Метод и маршрут:** `POST /api/pos/create-order`
- **Параметры:** Состав чека, тип оплаты (`Cash`, `Card`, `QR`), признак печати чека.
- **Ответ (200 OK):** Фискальный документ ООО «Элчос Пицца» с признаком расчета, ставкой НДС, номером ФД и ФПД.

## 6. Складской учет WMS, Маркетинг и Аналитика

### 6.1. Склад сырья (`/api/inventory`)
- `GET /api/inventory` — Реестр остатков (мука, сыр, соусы, мясные топпинги) в граммах и килограммах.
- `POST /api/inventory/update` — Корректировка остатка при инвентаризации (требуется роль `admin`).
- `POST /api/inventory/restock` — Оприходование новой партии поставки.

### 6.2. Промокоды (`/api/promocode/check`)
- `POST /api/promocode/check` — Проверка валидности кода (`ELCHOS20` - 20%, `ELCHOS15` - 15%, `PIZZA10` - 10%). Возвращает процент скидки и итоговую сумму к оплате.

### 6.3. Контроль качества и отзывы (`/api/reviews`)
- `GET /api/reviews` — Получение опубликованных отзывов гостей с оценками и текстом.
- `POST /api/reviews` — Добавление отзыва клиентом после получения заказа.

### 6.4. Аналитика и аудит (`/api/analytics`, `/api/logs`)
- `GET /api/analytics` — Сводка выручки, количество чеков, средний чек и топ продаваемых блюд.
- `GET /api/logs` — Системный журнал событий безопасности и аудита действий операторов.
